# محرك AL-ZOOL المركزي — نسخة التطوير

هذه الحزمة تعمل على **سيرفر المالك فقط**. لا توضع على جهاز العميل ولا تتضمن اتصال MT5 أو بيانات دخول الوسيط.

## ما تم نقله في هذه المرحلة
- كتالوج 200 استراتيجية (10 عائلات × 20 إعداداً).
- 1000 تركيبة فريدة، محسوبة من أصوات الاستراتيجيات الفعلية.
- حساب EMA وRSI وسياق السوق وجودة الدخول.
- تصويت العائلات المستقلة والتحقق الثانوي بالتركيبات.
- تخزين أوزان التعلم ونتائج الصفقات في SQLite على السيرفر.
- API لإصدار صلاحية عميل وإلغائها واستقبال بيانات السوق وإرجاع قرار موقع HMAC بمفتاح Bearer الخاص بالعميل.

## التشغيل المحلي على جهاز المالك
يتطلب Python على **السيرفر فقط**. لا يحتاج العميل إلى Python في التصميم النهائي.

1. أنشئ مفتاح إدارة عشوائياً بطول 32 حرفاً أو أكثر.
2. عيّن المتغيرات:
   - `ALZOOL_ADMIN_KEY`
3. من هذا المجلد شغّل: `python service.py`
4. افحص: `http://127.0.0.1:8765/health`

الإعداد الافتراضي يستمع على localhost فقط. لا تفتح المنفذ على الإنترنت مباشرة؛ النشر يحتاج VPS وHTTPS وجدار حماية ومراجعة إعدادات الاستضافة.

## API للمالك
إنشاء / تجديد صلاحية:
`POST /admin/client` مع ترويسة `X-Admin-Key` وجسم JSON يحتوي `client_id` و`days`.

إلغاء صلاحية:
`POST /admin/revoke` مع ترويسة `X-Admin-Key` وجسم JSON يحتوي `client_id`.

## API للعميل
إرسال لقطة السوق:
`POST /v1/market/{client_id}` مع Bearer token وجسم JSON: الرمز XAUUSD، bid، ask، و65 إلى 300 شمعة مغلقة.

استرجاع آخر قرار:
`GET /v1/decision/{client_id}`.

إرسال نتيجة صفقة للتعلم:
`POST /v1/outcome/{client_id}` مع deal_id وstrategy_id وpnl. يمنع تكرار النتيجة باستخدام المفتاح المركب `(client_id, deal_id)`.

## ما لم يكتمل بعد
- تجميع واختبار موصل MT5 محلي بصيغة Expert Advisor؛ مصدره يحتوي SL/TP عند الوسيط وTrailing محلياً وتحقق HMAC وتسجيل نتائج الإغلاق وإعادة إرسال النتائج المحفوظة عند عودة الاتصال.
- واجهة عميل Windows مستقلة EXE بلا Python.
- لوحة المالك لإدارة العملاء والأجهزة والتحديثات.
- ربط Supabase للمصادقة والاشتراكات والسجلات المركزية.
- اختبارات تكامل فعلية مع MT5 وحساب تجريبي.
- نشر محرك الخدمة على VPS وتشغيل مراقب دائم.

**مهم:** هذه المرحلة تنقل حساب الاستراتيجيات إلى السيرفر، لكنها ليست إصداراً جاهزاً للتداول أو للتوزيع على العملاء. لا تستخدمها على حساب حقيقي قبل اكتمال موصل التنفيذ واختبارات الانقطاع والتزامن.


## عقد استجابة القرار لعميل MT5

يرجع المساران `POST /v1/market/{client_id}` و`GET /v1/decision/{client_id}` كائن القرار مباشرة في المستوى الأعلى، وليس داخل غلاف `decision`. يتضمن الكائن الحقول `decision` و`decision_id` و`strategy_id` و`reason_ar` و`confidence` و`signed_payload` و`signature`. التوقيع HMAC-SHA256 يستخدم رمز Bearer الخاص بالعميل، ويتحقق منه EA قبل السماح بالتنفيذ.

**قيد أمني قبل التداول:** تمت إضافة التحقق من HMAC في مصدر EA، لكن لم يتم تجميع ملف MQ5 أو اختباره داخل MetaEditor حتى الآن. لا تعتبر النسخة جاهزة للتداول أو التوزيع قبل نجاح التجميع والاختبار على حساب Demo.


## تسجيل نتائج الصفقات

نتائج الصفقات مرتبطة بمعرّف العميل ورقم صفقة الوسيط `(client_id, deal_id)` لمنع تعارض أرقام الصفقات بين الحسابات. يرسل مصدر EA نتيجة كل صفقة مغلقة مع رقم الاستراتيجية والربح الصافي شاملاً العمولة والتبييت والرسوم. إذا تعذر الاتصال، تُحفظ النتيجة في Terminal Global Variables ويعاد إرسالها دورياً حتى يقبلها السيرفر؛ وبعد رد HTTP 200 تُحذف النسخة المحلية. deduplication في السيرفر يمنع التعلم مرتين من رقم الصفقة نفسه للعميل. هذه الآلية أضيفت إلى المصدر لكنها لم تُختبر بعد في MT5، ولا نعدّها مثبتة حتى ينجح التجميع واختبار الانقطاع.


## تكامل بوابة الويب الحالية

أضيفت بوابة المحرك إلى خادم الموقع نفسه عبر `/health` و`/v1/market/{client_id}` و`/v1/decision/{client_id}` و`/v1/analysis/{client_id}` و`/v1/outcome/{client_id}`. التخزين الدائم لمعرفات العملاء وبصمات الرموز والقرارات والأوزان والنتائج أصبح عبر جداول Supabase، وليس SQLite محلياً على Render.

قبل إنشاء حسابات عملاء جديدة، شغّل مرة واحدة ملف `server_engine/SUPABASE_ENGINE_SETUP.sql` في Supabase SQL Editor. عند إنشاء العميل من لوحة المالك، يصدر الخادم Client ID وClient Token فريدين ويضيفهما إلى ملف بيانات العميل القابل للتنزيل. عند إيقاف العميل أو حذفه، تُلغى صلاحية المحرك أيضاً.

رابط خادم MT5 الافتراضي هو `https://al-zool-gold-sniper.onrender.com`. يظل تنفيذ أوامر التداول محلياً داخل MT5 بواسطة EA؛ خادم الويب يحلل السوق ويوقع القرار فقط. لا يوجد شرط برمجي يميز حساب Demo عن Real. يجب ترجمة EA في MetaEditor واختباره على حساب تجريبي قبل استخدام حساب حقيقي.


## نقل إدارة الصفقات إلى المحرك المركزي — المرحلة الأولى

أضيف المسار الموثق:
`GET /v1/management/{client_id}`

المحرك المركزي يقرأ أحدث لقطة MT5 والإعدادات المحفوظة في لوحة التحكم، ثم يصدر أمراً قصير الصلاحية وموقعاً بـ HMAC. موصل MT5 يتحقق من التوقيع والصلاحية قبل تنفيذ الأمر.

**الوظائف المنقولة في هذه المرحلة:**
- هدف ربح الصفقة الواحدة.
- هدف ربح سلة الصفقات.
- حد الخسارة الإجمالية.
- حساب وقف الخسارة المتحرك وإرسال تعديل SL.

**ما لم ينتقل بعد، ولا يزال منطق تنفيذه في مصدر MT5:**
- التعافي الذكي.
- التعزيز والتبريد.
- حماية الانعكاس.
- ملاحقة الشموع والأوامر المعلقة.
- AI Loss Guard.
- حد الخسارة اليومي وبعض تفاصيل الربح الذكي.

لذلك هذه مرحلة انتقالية وليست بعد إصدار MT5 الجسر فقط. لا تعتبر النسخة جاهزة للتداول قبل نقل بقية الوظائف، وتجميع EA في MetaEditor، واختبار أوامر الفتح والإغلاق والتعديل على حساب Demo.
